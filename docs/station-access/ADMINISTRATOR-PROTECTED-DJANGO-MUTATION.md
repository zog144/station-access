# Protected administrator-password account mutation — source contract

Source-only successor to the disabled administrator HTTPS credential proposal (PR #9); receiving application is station-access. No route, CLI, enabled broker purpose, password source, or service is added.

`administrator_password_mutation.install_authorized(proposal, plaintext, proof, verify_root_admission=...)` is internal to the Django account owner. The `proof` is the exact nonsecret `zog-admin-credential-protected-handoff-v1` document produced by the independently protected host-install/root receiver after the canonical signed HTTPS v1 delivery is authenticated and durably recorded as delivered. A proposal, account export, browser permission, or caller-supplied `True` is not authorization. The root-attestor callback must be installed and protected by the native receiver owner, must not be supplied by an HTTP caller, and must re-evaluate the signed authorization, root ledger/nonce/request, HostIdentity and current local installation while the shared `SecurityGate` writer lock is held. Until that native owner exists, this function has no production invocation.

Within the existing `SecurityGate.locked()` transaction, the ceremony rechecks `station-admin` account PK, active superuser/staff, and keyed current opaque account revision, exact grant/approval/request/delivery/credential revision; rejects existing request/delivery ID and older/equal credential revisions from durable SecurityAudit; verifies first-login plaintext against the current hash only for first-provision or requires a genuinely new secret for rotate; calls the same Django `full_clean`, `validate_password`, `set_password` and `user_views.revoke` as the Users API; verifies old Django database sessions are gone and VNC access grants are revoked; and writes a secret-free `administrator-credential-installed` SecurityAudit row before returning the new account revision.

Passwords, encoded delivery envelopes, reusable secret digests, session cookies, VNC tokens, Django hashes and FIRST-LOGIN contents are never written into audit/proofs. The mutation returns only a readback witness with `shared_v1_receipt_signed=false` and cannot itself issue a receipt.

On ambiguous response, the owner calls read-only-in-effect `inspect_installed` using exact original IDs and expected new account revision. It returns installed only if SecurityAudit and current account revision match and revocations remain proven. Do not repeat the password write or restore an older hash on uncertainty. The root owner signs a shared-v1 installation receipt only after this account readback and persistent root ledger reconciliation. Cancellation after exposure requires a new revision/rotation.

This source deliberately does not activate an administrator-password receiver. It does not modify a live station DB; all tests use isolated synthetic Django databases. Required native follow-up: installed station source/RECORD, correct root/peer authorization under `SecurityGate`, durable canonical nonce + root ledger, actual anonymous-FD delivery, transaction/restart evidence, and signed HostIdentity receipt. It must not create canonical STATE on an externally-managed Command-Center.
