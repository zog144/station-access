# Protected station → managed Host Cloudflare credential transport

**Proposed supported profile:** dedicated, pinned-key SSH v2 **forced-command**, root-owned end-to-end secret streaming. **Status: source contract only; no cross-host executable broker, owner binding or native acceptance is supplied by this PR.** Consequently remote credential delivery remains **NO-GO** until the station/host privileged owners implement and independently accept it. This profile does not turn the station's existing local AF_UNIX reader into a remote endpoint.

## What is already implemented

The station's `issuer_cloudflare_reader` accepts a *local* fixed AF_UNIX, root-owned caller after kernel `SO_PEERCRED(uid=0)`, root-owned 0440 authorization projection, exact certificate/credential/zone/hostname verification and one-time nonce. On success it returns just bounded ASCII token bytes. The consuming `zog.root_control.issuer_station_transfer` requires the same local, root-owned socket and passes token through an anonymous FD to `issuer_credentials.install_from_fd`; it does not implement host-to-host transfer. Neither socket may be exposed on a network mount or reverse proxy. HTTP, Django API, beacon, websocket, SSH shell, generic remote command, SSM output and GitHub Actions artifacts are **not** credential carriers.

The `managed-dns01` certificate-only grant is the station's exact reviewed name authority for one enrolled generic Host. It is not a legacy `DnsDestination`, A record, issuer execution grant or permission to copy a vault key. Station reader may release a token **only after a separately approved signed managed certificate assignment and current nonsecret host-owner approval**, with all current grant/session/credential/zone checks passing before and after decrypt.

## Selected cross-host profile (owner implementation required)

1. The **managed Host root owner** opens an outbound SSH transport to a **fixed, isolated station credential bridge**. It pins a separately reviewed station SSH host public key, hostname/address, SSH implementation/source revision, and network endpoint; no TOFU, `accept-new`, loose `known_hosts` or agent forwarding. The station authenticates a distinct, restricted **client public key** that an operator has previously tied to the *actual* approved Host UUID, installation UUID, STATE UUID, HostIdentity key fingerprint, registry ID and selected issuer grant/storage. Merely asserting these identifiers in the request or having a valid station HTTPS connection grants nothing.
2. Station SSHD maps that client identity to exactly one fixed **non-shell forced command** under a dedicated transport UID, with `no-pty`, `no-port-forwarding`, `no-agent-forwarding`, `no-X11-forwarding`, `no-user-rc` and no arbitrary files/commands/subsystems. The forced command hands a bounded, one-shot nonsecret request to a **separately provisioned station root broker** over an exact local protected AF_UNIX endpoint. The broker authenticates its local service principal with `SO_PEERCRED` and independently checks the SSH-authenticated remote principal-to-Host binding. SSH peer credentials **cannot** be impersonated by the remote payload or passed through to the existing vault reader.
3. The station root broker may call the existing vault reader on the station's local socket as uid=0, only after independently checking the active root-owned station projection and its exact approval digest against the selected remote Host/installation, signed certificate assignment, current managed admission/hostname grant, revocation/highest revision and station authorization. The remote Host root separately validates its **own** root-owned approved assignment, installed signing authority pin, enrollment/STATE, issuer grant/storage and same digest *before* initiating transfer and *again* before committing secret installation. A station projection from another host or local project is not accepted.
4. One request per SSH connection, canonical ASCII JSON (maximum 1024 bytes), no caller-selected paths, methods, provider names or hostnames. The prospective transport schema is `zog-station-issuer-cloudflare-cross-host-v1`, with **exact** keys: `schema`, `operation="read-approved-cloudflare-issuer-token"`, `authorization_id` (64 lower hex SHA-256 of root approval), `host_id` and `installation_id` (canonical UUID), `assignment_id` (canonical UUID), `assignment_revision` (positive integer), `receipt_sha256` (64 lower hex), and `nonce` (32 lower hex). The station broker binds these to the **pinned SSH key identity**, exact grant and current local trusted approval, not to values supplied by the host alone. No remote request can select a token outside that grant.
5. Station root broker consumes and durably records the one-time nonce under a fixed principal/authorization scope *before* vault decrypt. The existing vault reader independently consumes a **separate** nonce. No replay or automatic recovery from a lost response; a fresh request requires the entire live authorization/revision/expiry chain to pass again. Use strict bounded reads/timeouts and require a single complete request. Audit only opaque assignment IDs/revisions, SSH-key fingerprint, authorization ID, nonce digest, outcomes and response length — **never token, token hash, terminal output or decrypted vault payload**.
6. Only after both approvals match, stream the **20–4096-byte** ASCII token as raw bytes over the authenticated encrypted SSH channel directly into the consumer's protected root process anonymous pipe/file descriptor, *not* a command string, shell variable, environment, PTY, filesystem handoff, CI artifact or log. Failures return **zero bytes** (not a secret-bearing diagnostic). The consumer validates exact byte grammar and length; call `install_from_fd` under its original root-controlled state and identity locks. Root-controlled private `0700` issuer state and `0600` token file are the only durable plaintext location. The station vault source stays on the station.
7. Invalidate/revoke the station-side host transport key on Host/installation/STATE/signer/registry/key replacement, session expiry, hostname grant withdrawal, credential revision, assignment revocation or protected issuer owner policy changes. Old key approval, root authorization and nonce history must never be silently reset by reinstall/reboot. Disable bridge admission by default; no opportunistic fallback to generic HTTPS or direct remote shell.

The host owner's `issuer_station_transfer transfer` currently supports **local** socket transfer only; a future explicit `cross-host` owner entry point must implement this profile (or a separately reviewed equivalent) and must never reinterpret `transfer` to open a network connection implicitly. The station-side broker must not run as the station web UID or be a Django HTTP view. Protected SSH keys are distinct from the generic application/VNC/workspace identities. Production admission additionally needs verified station endpoint routing, host-side genuine installed-byte attestations and agreed key lifecycle/rotation.

## Native acceptance / stop conditions

Before the first real token delivery: independently authenticate the actual SSH server key and the client transport key; attest both installed source trees, root/writer and vault-reader UIDs, protected service/socket DAC, station/host separately approved matching digests and signed history; verify no command/forwarding/PTY/shell access; wrong Host/installation/STATE/registry, changed signer key, changed hostname/zone, old credential revision, expired session, revoked assignment, missing station projection, nonce replay, mid-read rotation and cross-host key substitution all fail **before any token emission**. Test incomplete SSH read, canceled transfer, process crash, reboot and stable original grant/storage. Confirm zero token bytes in journal/argv/environment, SSH logs, SSM, HTTP responses and artifacts; verify receiver file and exact issuer selected inspect with fresh native receipts.

**Current disposition: protocol defined, transport implementation NOT RUN / NOT AUTHORIZED; no provider writes, credential export, DNS TXT/A records, ACME issuance, root policy activation or controller state change.** The station source reader and local AF_UNIX owner remain the only implemented secret interface. A successful GitHub CI run proves source behavior, not that this cross-host path exists.
